# backend/scripts/

One-off / operational scripts, run directly rather than imported by the app
(`python -m backend.scripts.<name>`). Scripts here reuse the app's existing
session factory, models, and utilities — they never reimplement database
connections, hashing, or auth logic.

- `seed.py` — seeds baseline development data (default users incl. a
  supervisor, demo customers, demo tickets, and knowledge-base articles for
  `KnowledgeBaseSearchTool` to actually retrieve). Deliberately does *not*
  create any `approval_requests`, `agent_runs`, or `audit_logs` rows -- those
  are operational data generated by using the application, not fixtures.
  Idempotent: safe to run more than once -- and the knowledge-article
  backfill has its *own* idempotency check, independent of the
  users/customers/tickets one, so re-running against a deployment that was
  already seeded before `knowledge_articles` existed still backfills them.
  See its module docstring for details.
- `load_test.py` — logs in as the seeded supervisor, then fires 50
  concurrent requests at `POST /supervisor/queue/{ticket_id}/reject` and
  reports latency/throughput; requires the app to already be running
  separately (`uvicorn backend.main:app`) against a database seeded via
  `seed.py`. Deliberately targets this endpoint rather than `POST /tickets`
  (which exists, but its OpenAI/CrewAI calls would make external LLM
  latency the bottleneck, not this app's own routing/auth/rate-limiting).
  Since `seed.py` creates no pending reviews, the target ticket ID 404s
  unless one has been escalated since -- expected, and still exercises real
  auth/rate-limiting regardless (see the module docstring). Sample ticket
  payloads live in `load_test_tickets.py`.
- `export_workflow.py` — renders the compiled LangGraph workflow to
  `workflow.png` (Mermaid, via `graph.get_graph().draw_mermaid_png()`) --
  used to produce `docs/screenshots/02-workflow.png`.
- `test_openai.py` — manual connectivity smoke test: one `ChatOpenAI`
  (`langchain-openai`) call against `settings.openai_api_key`/`llm_model`,
  logs the response. Not used by `classify_ticket`/`SpecialistAgent`
  (those call OpenAI directly and via CrewAI, respectively) -- just a
  quick way to confirm credentials/connectivity independently of either.
